ARCHITECTURE

Canonical chain state, rebuildable relational reads

Read and write model

REST request → relational execution → read: current projection snapshot
                              └→ write: deterministic WritePlan
                                           → authorization → chain commit

Chain state is canonical. The gateway can maintain a local relational projection for joins, CTEs, views, aggregates, and window functions, but that projection is not an independent source of truth and must be rebuildable. A normal read must not intentionally return an old projection while the current chain head is known.

Signed sessions and trusted execution

A self-signed wallet session or instance-configured identity authority identifies the caller. The contract validates gateway delegation, session binding, gateway epoch and expiry. It does not prove per-table approval or the result of arbitrary SQL: RLS, constraints, and function semantics run inside the explicitly delegated gateway. The gateway may execute within that delegation, but cannot mint new authority.

SQL semantics and limits

The semantic reference is ISO SQL:2023 with necessary PostgreSQL/Supabase-style extensions, not a claim of complete SQL conformance. Expected coverage includes normal relational queries, mutations, constraints, RLS, returning/upsert, selected views, and SQL-language RPC. Unsupported features must report an error. No PostgreSQL wire protocol is provided.

Public-chain confidentiality caveat

Do not store secrets, personal data, access tokens, or data that needs conventional database confidentiality in public chain state. Encryption design, key management, and metadata leakage are separate concerns and are not solved by a relational API.
